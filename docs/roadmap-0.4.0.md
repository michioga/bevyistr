# 0.4.0 開発計画（2026-11-01）

基準は公開済みの **v0.3.0**（タグ `794a994`）です。次版を0.4.0候補として開発を始めます。
この文書は計画であり、対応機能・公開日を約束するものではありません。
版番号・依存バージョンは公開範囲が固まるまで0.3.0のままにします。

## 第三者レビューの扱い

レビューの「UIへの責任集中」「性能の実測不足」「失敗時の検証不足」を改善候補に採用します。
ただし、コードを直接確認して再現・計測した問題と、懸念・推測を区別します。
「毎フレーム再構築」「メモリリーク」「実行検証の抜け穴」はレビューだけでは確定しません。
他ツールの保守状況や優劣も未検証なので、紹介記事やマニュアルの比較表へ転記しません。

レビュー前半の「公開版0.2.0／0.3.0開発中」は現在と異なります。
公開記録は[0.3.0リリース記録](release-0.3.0.md)、利用者向けの基準は0.3.0マニュアルです。
古い[0.3.0計画](roadmap-0.3.0.md)は当時の履歴として残します。

## 実装の優先順序

1. **結果表示の性能を測り、確認できた無駄を減らす。**
   プローブ、コンター再構築、読み込み、選択を別々に計測する。
   静止時・ホバー・フレーム変更・変形倍率変更で何が再構築されるかを回帰テストで確認する。
   測定環境・メッシュ規模・形式・ビルド種別・計測範囲を記録し、未測定の上限を宣伝しない。
2. **UIの責務を小さく分け、操作を通したテストを追加する。**
   まず結果プローブのキャッシュを表示から切り離す。
   次に結果読込・Solve実行などの状態遷移と表示の境界を点検する。
   機械的な大移動や公開クレート追加を先行させず、数値・選択・Undo等の既存仕様を守る。
3. **ソルバー失敗・中止・再実行の復帰を検証する。**
   分割失敗でソルバーが始まらないこと、Stop後の子プロセス・ログ・実行ボタンの状態、
   古い結果の誤読込防止を小さなプロセスfixtureで再現し、不足分を補う。
   実機MPI確認とfixture成功を区別する。例題・元入力を破壊するクリーンアップは行わない。
4. **解析設定の対応範囲を、利用者が判断できる形で整理する。**
   GROUP／ACTIONの単体保持と、複数部品統合時の参照制限を明記する。
   名前付き出力GROUPの参照変換は候補として、公式仕様・現コード・往復テストを照合して採否を決める。
   未対応カードを黙って捨てないガードを維持する。
5. **操作感・情報密度を改善する。**
   リリース後へ持ち越したSolidCraft風カメラ操作を再検討する。
   既存操作の保存、選択／姿勢編集との干渉、回転中心・極付近の挙動を検証する。
   HISTORY／COMPARISONの折りたたみは、警告と保存対象を隠さず状態を維持できる場合に検討する。
6. **公開範囲の確定と検証・配布。**
   Windows／Linux CI、設定保存・再読込、結果／CSV、配布物、監査、マニュアルを確認する。
   機能の区切りでcommitし、公開時にmainへ統合、版番号・内部依存・タグ・crates.io・Windows ZIPを揃える。
   コミット・push・タグはメンテナーが行う。公開済みv0.3.0は変更しない。

## 最初の区切り: プローブのキャッシュと計測

作業ブランチ: `perf/result-probe-cache`（main `cb4c1b2`から開始）。

- 確認した問題: `VisualizationSettings`全体の変更フラグでプローブのBVHを破棄していたため、
  Wire等の描画モード変更や同じ値の代入後にも、次のホバーで再構築していた。
- 改善: 結果・モデル更新は引き続き破棄対象とし、コンター設定は値を比較する。
  再生／UI操作中も無効化を記録し、次に必要になったときだけ構築する。
- テスト: 表示モード・同値代入で再利用、再生中のフレーム変更後に正しい値を取得、
  変形・物理量・モデル差替え・欠損フィールドで古い幾何を使わないこと。
- CPU計測: 合成Hex8格子の準備、変形面BVH構築、キャッシュ済み4096レイの照会を分離する。
  [計測手順](performance.md)に従い、描画FPSや大規模実モデルの保証と混同しない。

検証（2026-11-01）: UI 214件・可視化33件成功、失敗0、実機MPI依存1件スキップ。
`cargo +1.99.1 test -p bevyistr-ui -p bevyistr-visualization --lib --locked --offline`を使用。
Release計測例は729～274,625節点の4規模で全4096レイの値・距離を確認した。
mdBookビルド、変更したRustファイルの整形検査、diff空白検査に成功。
TEMP／TMPとリンクのPDB無効化は検証プロセス内だけに指定した。
GUI実機操作とLinux実行、実データの速度・メモリは今回未確認。

## 今回の必須範囲にしないもの

- FrontISTR全キーワード、非線形材料・熱／流体入力・連成・周波数応答の全面対応。
- バイナリVTK、PVTUの溶接・平均化、トポロジー変化を伴う系列。
- Bevyの更新そのもの。機能制御・依存監査・描画とUIの回帰を確認して別途判断する。
- 流体例題の再解析・問題修正。FrontISTRサポートへの問い合わせ待ちを維持する。

## 次の区切り: 実データ計測とVTK登録時の二重構築削減

`87ed246`のcommit／push後、同じ性能改善ブランチで継続しました。
合成格子に加え、外部VTU／PVTUを読み取り専用で扱う手動計測テストを追加しました。
読込、先頭／最終フレームのコンター面・ワイヤー・プローブ、選択の境界面候補取得を分離します。
選択UI全体やFPS、最大メモリ使用量はこのテストでは測りません。

conrodの2フレームで、再読込中央値855.835ms、コンター面約6～8msを観測。
VTK登録で既に作成済みのトポロジーを二重構築していたため、ローダー内の登録だけを改善しました。
修正後の再読込中央値は673.305ms（この環境で約21%減）でした。
後続フレームの形状照合やゴースト処理・区画ID対応は維持します。
hinge／heatでも面とワイヤーの整合を確認。測定条件・再現コマンドは[計測記録](performance.md)を参照。

検証（2026-11-01）: HECMW 101件・UI 214件・可視化33件成功、失敗0。
通常実行では外部例題依存5件、実機MPI依存1件、手動性能計測1件をスキップしました。
性能計測は別途Releaseで3例題を実行して成功しました。GUI実機・Linuxでの実行は今回未確認です。

残る性能課題は、実データでの複数区画・RES・選択操作全体・メモリ計測です。
この時点では後続フレームでもトポロジーを構築して形状照合後に破棄する経路が残っていました。
以下の「連番VTKのトポロジー構築」で改善します。

## conrodの設定保持警告（2026-11-01）

メンテナーからModel／Resultsの画像を受領し、元の`conrod.cnt`を読み取り専用で照合。
検出26件は、BOUNDARYのGRPID省略1件、ソルバーPRECOND=3の保持制限1件、
FrontISTRの描画・可視化出力の記述24件だった。解析の不備26件という意味ではない。

- 警告を`Setup incomplete`から`CNT re-export blocked`へ変更し、bevyistrによる設定保持の制限と明記。
- Resultsでは保存済み結果を閲覧できることを表示。Solveでは詳細が下にあることを案内する。
- 未対応設定の検出・Export／Runの停止条件は維持する。対応範囲を増やす変更ではない。
- ページ切替だけで案内が更新され、ソルバー編集でも警告詳細が保持される回帰テストを追加。
- `hecmw`の`inspect`例に任意のCNT引数を追加。MSHとCNTを読み、保持制限のファイル／行／理由を出す。

画像は読み込みと表示の確認資料であり、解析値の妥当性を保証する資料としては扱わない。
描画設定の丸ごと保持、ソルバーの前処理設定、GRPID省略の対応拡張は別途の往復テストとともに検討する。

## 連番VTKのトポロジー構築（2026-11-01）

`f927d79`のcommit／pushとクリーンな作業ツリーを確認し、同じ性能改善ブランチで継続。
VTK解析／ゴースト除去はトポロジー未構築の専用型で行い、先頭フレームの確定形状でのみ
FemMeshを作成するよう分離しました。後続フレームの座標・接続・区画数・ID・ゴースト情報の検査は維持します。
出力フィールドやモード／時刻、配列の値、区画間の色範囲の仕様は変更しません。

- 新しい回帰テスト: 後続フレームの接続変更／区画数変更を拒否。
  ゴースト除去後の形状が一致する場合は値を保持し、所有セルのローカルIDが変わる場合は拒否。
  後続フレームの未対応ゴーストフラグ・非表示セルも検査する。
- HECMW 103件、UI 214件、可視化33件成功（計350件）。失敗0、例題／実機MPI／手動性能計測の7件は通常実行でスキップ。
- Release実測: conrod 2フレーム682.309→511.370ms、円柱6フレーム17.962→9.183ms、
  ばね5モード1110.947→504.826ms（各5回の再読込中央値）。条件と限界は[計測記録](performance.md)を参照。
- 実データ3例題で先頭／最終フレーム・変形OFF／倍率1／倍率5の面とワイヤーの整合を検査。
  元データは読み取り専用。FrontISTR再解析・流体例題の検証は行わない。

次の候補は実データでの複数区画／RES・選択操作・メモリ計測と、結果読込の状態管理の境界整理です。
アプリ全体のFPS、GUI実機とLinux実行、扱えるモデルサイズの上限は今回の計測では保証しません。

## ネイティブRESの文字列解析（2026-11-01）

`e237f56`のcommit／pushとクリーンな作業ツリーを確認し、同じ性能改善ブランチで継続。

通常の数値ごとの文字列確保を削減しました。D／d指数の正規化、V1／V2、固有値のf64精度は維持します。

- `hecmw/examples/benchmark_results.rs`: MSH・RESの読込、単一ファイル解析、ID配列化、系列全体を別々に計測。
  比較用signatureで、ID順・全フィールド値と範囲・Step／Time／Eigenvalueを確認する。
- 回帰テスト: LF／CRLF、末尾改行なし、Unicodeコメント、V1／V2、E／D／d指数、
  不正セクション・余分な値・欠落・重複ID・非有限値の拒否。
- HECMW 105件、UI 214件、可視化33件成功（計352件）。失敗0、外部例題／実機MPI／手動性能計測の7件は通常実行でスキップ。

  各5回中央値。3例題とも結果の比較用signatureが変更前後で一致した。
  対象範囲と再現手順は[計測記録](performance.md)にまとめる。
- 元例題は読み取り専用。ソルバー実行・流体例題の検証、GUI実機・Linuxの確認は行っていない。
