# 0.3.0 開発計画（2026-09-21）

これは開発者向けの計画であり、実装済み機能の説明や公開日の約束ではありません。
公開済みの基準はv0.2.0です。アプリの版番号は今ここでは変更せず、
0.3.0の公開範囲と検証が揃った段階で更新します。

## 方針

「操作はビューポートで直観的に、確認は厳密に」を維持します。
0.2.0で実装した結果読み込み・動的フィールド選択・固定プローブ・履歴表示を基礎に、
結果を数値として持ち出し、比較できる流れを優先します。
解析入力の設定と結果表示を混同せず、未知の単位や成分の意味を推測しません。

## 実装順序と区切り

### 1. 単一固定プローブの履歴CSV保存

想定ブランチ: `feat/probe-history-csv`。

Resultsで「表面をクリックして固定 → HISTORYを確認 → Export history CSV」の順に操作します。
保存操作は履歴の近くに置き、別ページへの移動や解析の再実行は不要とします。

受け入れ条件:

- 固定した部品番号と節点／要素ID、選択物理量、読み込んだ全フレームを出力する。
  部品をまたぐ同一IDを混同しない。画面のIDとCSVのIDの対応を明示する。
- Frame番号、元のStep、記録されたTime／荷重係数、値を区別する。
  時刻が重複・逆行・未記録でもフレームを並べ替えず、物理的な時間と断定しない。
- 節点値と要素値を相互変換しない。ベクトルの大きさと成分を区別する。
  変形倍率とコンター色範囲を変えても、保存される解析値は変わらない。
- 欠損・非有限値はゼロ埋めしない。値は空欄、別の状態列で利用不能と分かるようにする。
  単位は結果／モデルの単位系のまま扱い、N、Pa、秒などを推測で追加しない。
- 数値は表示用の丸めを再利用せず、保存されている精度を保つ表記を使用する。
  小数点はロケールに依存させず、文字列のカンマ・引用符・改行を適切にエスケープする。
- 保存ダイアログを開いた時点の対象・物理量・結果を一貫したスナップショットとして扱う。
  保存待ちの間のフレーム変更や再読み込みで別データにすり替わらない。
- 固定対象がない場合は理由を表示する。キャンセルはファイルも解析設定も変更しない。
  上書きを確認し、書き込み失敗はUIに表示する。ダイアログや保存で描画を止めない。

実装の出発点は`ui/src/probe_history.rs`と`ui/src/result_probe_pin.rs`。
グラフとCSVで異なる値の抽出処理を持たないよう、履歴データの生成と描画／保存を分けます。
CSV保存とダイアログは小さな専用モジュールに分離し、`layout.rs`へ処理を追加し続けません。

テスト:

- 節点／要素、複数部品の同一ID、成分／大きさ、欠損、NaN／Inf、一定値、1フレーム。
- 不等間隔・重複・逆行する時刻、飛び番Step、特殊文字を含む物理量名。
- コンター／変形倍率の変更からの独立性、保存時のスナップショット、キャンセル／I/O失敗。
- 円柱の複数フレームでPINNED欄・履歴・CSVの値が一致する手動確認。

### 2. 複数対象の比較

`feat/probe-comparison`で、明示的な「比較に追加」、最大4対象の色・ID一覧、個別解除、共通縦横軸の履歴表示を実装します。
通常クリックで現在の対象を置き換える既存操作を壊さないことを優先します。
多数のグラフや常時表示ボタンを先に増やさず、単一対象の保存が使いやすいことを確認してから進めます。
異なる物理量や単位を同じ軸で暗黙に比較しません。

### 3. 高度なモデルでの結果検証と必要な修正

既存の`D:\Work\FrontISTR\tutorial`を読み取り用の参考とし、元データを上書きしません。
その絶対パスをアプリやCIの必須条件にせず、小さな合成fixtureで自動回帰テストを用意します。

- `03_hyperelastic_cylinder`: 連番、変形、節点／要素量、履歴と保存値。
- `12_dynamic_beam`: 飛び番Stepと時刻、速度／加速度など実出力フィールド。
- `15_eigen_spring`: 実ファイルのメタデータを調べ、モードを時間履歴として誤解させない表示。
- `16_heat_block`: 実際に出力された温度等のフィールド選択・凡例・プローブ。
- `18_cavity_flow`: 複数PVTUピース、PRESSURE／VELOCITY、一定値成分、部品ローカルID。
- `19_conrod`: 大きなメッシュ、未使用節点、読み込みと操作の応答性。

モデル名だけで対応済みと判断しません。検証記録にファイル・フィールド・結果を残します。
Solveで編集する出力項目の拡張は別の区切りとし、必要な場合は公式マニュアルと
FrontISTRソースを照合して追加します。Resultsは引き続き実ファイルからメニューを構築します。

## 今回の必須範囲にしないもの

バイナリ／appended VTK、PVTUのグローバルID統合、クリッピング、
トポロジーが変化する系列、FrontISTR全キーワードの編集は独立した大きな課題です。
0.3.0での対応を現時点では約束しません。既存の読み込みや数値の正確さを優先し、
未対応形式を誤った結果として表示しない方針を維持します。
